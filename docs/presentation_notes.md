## Вероятные вопросы

- **Почему Recall на тесте ниже, чем на кросс-валидации?** Внутри одинаковых диапазонов RUL качество одинаковое; в тесте 63% положительных строк в трудном диапазоне 21–30 циклов (в train 32%), потому что наблюдения обрываются до отказа.
- **Почему не подобрали порог так, чтобы выполнить Recall?** Порог, выбранный по тестовой выборке, — подгонка: оценка перестала бы быть честной. В эксплуатации порог уточняют в теневом режиме на новых данных.
- **Почему логистическая регрессия, а не бустинг?** Лучшее PR-AUC на 10 блоках, бустинг значимо не лучше (p = 0,98), регрессия проще, быстрее и интерпретируема.
- **Как избежали утечки данных?** Разбиение и кросс-валидация по двигателям; окна признаков только по прошлому (тест); неинформативные столбцы определялись только по train; модель с одним номером цикла даёт PR-AUC 0,51.
- **Что будет, если consumer упадёт?** Смещение фиксируется только после записи в БД, поэтому пачка будет прочитана заново; дубли отсекаются уникальными индексами, а прогнозы восстанавливаются по истории из raw.
- **Откуда 30 циклов = 7 дней и 10 : 1?** Допущения: ≈ 4 полёта в сутки; соотношение стоимостей — экспертная оценка.
- **Зачем web scraping, если данные не входят в модель?** Обогащение справочником (требование блока 4.1); показывает, что C-MAPSS ближе всего к Trent 800 и GE90; в модель не входит, т. к. у всех двигателей FD001 один тип.
